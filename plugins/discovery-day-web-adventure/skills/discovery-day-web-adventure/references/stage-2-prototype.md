# Stage 2 - Prototype

## Purpose and milestone

Purpose: turn the approved Site Brief into a working one-page website and a private Sites preview the attendee can see and use.

Milestone: the attendee has explicitly authorized a workspace-private preview, and that rendered preview is visibly open in the built-in browser side panel.

## Build the first version

Use the stage label **Web Adventure - Stage 2 of 4: Prototype**. Briefly recap the approved Site Brief and name any unresolved assumptions before building.

Build only the agreed first version. Use real attendee-provided material when available; otherwise use clearly generic placeholder content that can be replaced. Keep the page responsive, readable, and keyboard-friendly. Do not add features merely because they are technically possible.

Before deployment, ask a direct question such as:

> Shall I create a private Sites preview for you to review? It will be available only within this workspace and will not be public.

Wait for a clear yes. Then use Sites to create the attendee's own private preview and open its URL visibly in the built-in browser side panel. Inspect the rendered private page, not only the source code or a successful build command. Do not require the attendee to run a local web server, use a port, or install development software.

If the private preview cannot be created or opened in the built-in browser, explain the blocker and keep the site unshared. Do not say it is ready for annotation until the attendee can see the rendered private page.

## Stage close

Summarize what was built, what uses placeholder content, and where the private preview is open. When the rendered page is visibly available, announce Stage 2 complete and remind them to collect the Prototype stamp.
